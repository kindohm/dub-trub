# Domain docs

This repository uses a single-context layout.

Before exploring the codebase, read root GLOSSARY.md and
ADRs in docs/adr/ relevant to the work.

If these files are absent, proceed silently. Domain-modeling
creates them as terms and decisions are resolved.

Use the glossary's vocabulary in issues, code proposals,
and tests. Note real terminology gaps for domain-modeling.

Surface conflicts with existing ADRs explicitly, identifying
the decision and the reason to reconsider it.
